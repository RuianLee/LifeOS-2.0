# LifeOS 2.0

> 以「遊戲」作為單位，來進行生活與專案管理

## 核心理念

一般的生活以 todo 為單位，預設的是「**該做的事**」，所以需要外力催促。LifeOS 2.0 改用「**遊戲**」當作單位，管理的是「**想做的事**」。

> 玩遊戲，就是自願去克服不必要的障礙。— Bernard Suits *The Grasshopper*

## 遊戲最大的不同在於它**有邊界**：

- **有開局**：明確知道從哪一天開始玩
- **有結束**：有期限，不會變成永遠做不完的感覺與義務
- **有勝負**：有勝利條件，結束後可以結算

一局結束後，可以自願決定要不要開下一局。

## 遊戲的四個元素

每一局遊戲都要具備以下四個元素：

| 元素 | 說明 |
|---|---|
| **目標** | 自己覺得好玩、不需要別人催促的事 |
| **規則** | 一組讓事情變有趣的限制 |
| **回饋系統** | 看得見的自然結果，例如作品、紀錄、規模 |
| **自願參與** | 可以自由開局，也可以退出；過程中會成長，也會被看見 |

## 規則：設計「不必要的障礙」

規則是好玩的來源，不只是限制。打高爾夫最快的方法是用手把球拿進洞，但規則禁止這麼做，遊戲才變得好玩。

> 例如，「讀書」每天讀 20 分鐘，只能讀紙本，讀完要用一句話講給某人聽。

**設計遊戲，就是設計一組讓事情變有趣的限制。**

## 回饋：重視自然結果，不靠人工積分

回饋來自做事本身留下的成果，而不是外加的點數或徽章：

- **作品**：做出來的東西、連結、截圖
- **紀錄**：過程中的軌跡與反思
- **規模**：可量化的成長，例如字數、使用者數、距離

## 一局遊戲的生命週期

```
idea → playing → ended
                  ├─ 續作：開下一局
                  ├─ 改規則：調整後重開
                  └─ 封存：這款遊戲下架（不算失敗）
```

## 專案結構

```
LifeOS-2.0/
├── ReadMe.md
├── .vscode/
│   └── game.code-snippets   # 開局模板
└── games/                   # 每一局遊戲是一個 Markdown 檔
```

- 一局遊戲對應 `games/` 裡的一個檔案，結構保持扁平，不使用巢狀資料夾
- 遊戲狀態、日期、領域等資訊記錄在檔案開頭的 frontmatter
- 修改規則就是一次 commit，git 歷史本身就是成長紀錄

## 開新的一局

1. 在 `games/` 新增檔案，例如 `2026-11-作品集網站.md`
2. 輸入 `game`，選擇建議中的 **LifeOS Game**
3. 按 Tab 依序填寫：標題、狀態、領域、結束日、目標、規則、勝利條件

| 欄位 | 值 |
|---|---|
| `status` | `idea` / `playing` / `ended` |
| `domain` | `專案` / `學習` / `健康` / `人際` |
| `start` | 自動帶入今天 |
| `end` | 賽季結束日 |

## 願景

- **桌面應用程式**：將 `games/` 視覺化成遊戲庫、賽季進度與作品牆，讓每天打開都感到興奮
- **共同開局**：從一個人玩，發展成邀請別人一起開局
