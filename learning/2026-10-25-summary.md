## 學到的觀念

### Electron

| 觀念 | 重點 |
|---|---|
| 兩個程序 | **主程序**（Node.js，可讀檔、開視窗）和**畫面**（Chromium，只負責呈現），中間用 IPC 溝通，preload 是唯一的橋 |
| 生命週期 | 一定要等 `app.whenReady()` 之後才能 `new BrowserWindow()` |
| 歡迎頁 | 看到 Electron 的歡迎頁＝沒載入任何 App，檢查「在哪個資料夾執行」和「有沒有帶 `.`」 |
| 結束程式 | Mac 上關掉所有視窗不會結束 App，要自己處理 `window-all-closed` |

### Node.js

| 觀念 | 重點 |
|---|---|
| 模組系統 | CommonJS（`require`）vs ES Module（`import`），由 `package.json` 的 `"type": "module"` 決定 |
| `__dirname` | ES Module 沒有 `__dirname`，改用 `import.meta.dirname` |
| 絕對路徑 | 用 `path.join(import.meta.dirname, ...)` 組路徑，不管從哪裡啟動都找得到檔案 |
| npx | `npx X` 會先找專案的 `node_modules/.bin`，找不到才臨時下載；跑錯資料夾就會用到不同版本 |
| npm scripts | 把常用指令寫進 `scripts`（`npm start`、`npm run format`），就不會打錯 |

### 工具

| 觀念 | 重點 |
|---|---|
| Prettier | `.prettierrc` 定規則，VS Code 擴充負責存檔時執行，CLI（`npx prettier --check`）負責檢查 |
| VS Code 設定範圍 | 只讀「開啟的那一層」的 `.vscode/settings.json` |
| 未存檔的 buffer | 檔案被外部修改時，按存檔會把舊內容蓋回去；用 **File: Revert File** 重新載入 |

### 程式風格

- `main.js` 當**目錄**：只描述「什麼時候做什麼」，細節放在獨立的函式或模組裡
- 註解寫「為什麼」，不要寫「做什麼」，旁白式註解很快就會和程式碼對不上（400×560 vs 700）

## 除錯的方法

今天三次失敗，有兩次答案就寫在畫面上：

1. **讀完錯誤訊息和 Usage**：`Usage: electron [options] [path]` 已經說了要帶路徑
2. **從線索往回推**：歡迎頁上的 `../.npm/_npx/...` 透露了「在哪裡執行」和「用的是哪一份 Electron」
3. **確認硬碟上的真實狀態**：編輯器看到的不一定是存在硬碟上的內容（0 bytes 的 `main.js`）
